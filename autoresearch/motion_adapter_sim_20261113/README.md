# Motion-Aware MC-GS：hyw 数据上的运动仿真验证

在 hyw 的真实多线圈 k 空间上加入已知的 T2W 运动（扫描间刚体/非刚体、扫描内分段刚体）和对比度特有病灶，
检验给共享高斯加一个轻量运动适配器后，MC-GS 能否找回运动并保住 T2W 质量，零运动时不添乱。

- 设计：`docs/superpowers/specs/2026-11-13-motion-adapter-sim-design.md`
- 实施计划：`docs/superpowers/plans/2026-11-13-motion-adapter-sim.md`
- 分支 `exp/motion-adapter-sim-20261113`，worktree `mcgs/.claude/worktrees/motion-adapter-sim`
- 服务器根目录：`codex_artifacts/mcgs_motion_adapter_20261113/`（`trainer/`、`data/`、`configs/`、`ledger.jsonl`）

## 运行

在 worktree 根目录、本机上执行。`tools/rrun.py` 用 worktree 私有的 gpu.py 配置（`.claude/gpu/config.json`，
`repo` 指向本 worktree）快照并上传本 worktree，在 amax 上运行一条命令，跟随日志，并以作业的退出码退出。

```sh
E=autoresearch/motion_adapter_sim_20261113
/usr/bin/python3 $E/tools/rrun.py --cpu -- @python $E/tests/run_tests.py            # 全部 CPU 测试
/usr/bin/python3 $E/tools/rrun.py --cpu -- @python $E/tests/run_tests.py tests/test_geom.py
/usr/bin/python3 $E/tools/rrun.py --gpu ID --detach -- @python $E/run.py ...        # 训练，立即返回作业号
```

## 规则

- 时间只用本机时钟。服务器上不读任何时钟、文件时间或程序自己量的耗时；`tests/run_tests.py` 在服务器端删去
  pytest 的耗时，本实验的代码不打印、不写入任何时钟值。账本里的启动/结束时间是本机时间。
- GPU：启动前两次检查（间隔约 75 秒）都为空的卡才用；一卡一作业；不动别人的作业。
- GT、ROI、病灶掩模、运动真值不进训练（oracle 组除外，表中标注）。
- 适配器设置只在开发条件 D1–D3 上确定，冻结后才跑测试条件。

## 开发记录：适配器设置（任务 8，2026-11-14 至 11-15）

设置只在开发条件 D1–D3 和 C0 上确定。重建数据后共 10 次调参训练（上限 10），另有 4 次在作废数据上的 r1。
评分为头部 PSNR（dB），T1 / T2；D3 的带分段位姿的组用“只插回参考段”的数据一致性评分（设计 11.1）。

| 轮次 | 改动 | 运行 | 结果 |
|---|---|---|---|
| r1 | 起始设置 | C0/A2、D1/A1、D2/A2、D3/A3 | 在方向错误的旧数据上，只作诊断：位姿 4000 步只动了 0.1 mm / 0.02° |
| r2 | 只加 `adam_eps = 1e-12`（当时的假设：位姿梯度远小于 Adam 的 eps） | C0/A2、D1/A1、D2/A2、D3/A3 | 没有效果，假设被否定（见下） |
| r2 对照 | 不改设置 | D1/A0、D1/O、D3/A0、D3/O | 真值变换的收益：D1 +0.02 / +0.01 dB；D3 的 T2 +1.5 dB |
| r3 | 只改阶段边界 `stage_iters = [0, 0]`（非刚体和分段位姿从第 0 步放开），去掉 `adam_eps` | D3/A3、C0/A2 | D3 的 T2 +0.21 dB，分段位姿方向正确、幅度为真值的 10–30 %；C0 关卡通过 |

**结论（开发条件上）**

1. 零运动不伤害：C0 下 A2 与 A0 相差 −0.002 / −0.001 dB，脑内非刚体位移 0.002 mm，关卡通过。
2. **适配器没有找回运动。** 扫描间：D1、D2 的 TRE 与不做任何校正相同。扫描内：分段位姿只走了真值的 10–30 %。
3. 原因（r2 起记录在 `<exp>_motion.json` 的梯度统计）：位姿梯度并不小（平移约 5e-5 每 mm，旋转约 5e-3 每弧度），
   但 200 步窗口内的符号一致性只有 0.00–0.05，即位姿停在一个尖锐谷底里来回摆。训练器的 `shared_warmup_iters`
   已不起作用，两种对比度的密度从第 1 步起各自独立，并且按 T2 数据所在的位置初始化；T2 的数据一致性项因此等价于
   “T2 渲染对 T2 数据的配准代价”，在位姿 0 处已经最小。把位姿拉向真值的只有“共享几何用得更省”这一间接收益，
   梯度下降看不到它。扫描内同理：带伪影的图像本身就能拟合被运动污染的 k 空间。
4. 扫描间错位对图像质量的影响很小：D1 上给定真值变换只多 0.02 dB（T1）/ 0.01 dB（T2）。按设计第 12 节，
   这属于“A0 没有明显下降，问题在该幅度下不显著”。
5. 扫描内运动的影响大：D3 的 T2 比 C0 低约 3.9 dB；给定各段平均真值位姿收回 1.5 dB（8 段平均位姿不能表示段内的
   连续漂移和阶跃），冻结设置的 A3 收回 0.21 dB。
6. 只读探针 `probe_reginit.py`（CPU）：只用 AF12 的零填充 T1、T2 做 NGF 刚体配准，差分 TRE 在 D1 为均值 0.04 mm、
   最大 0.08 mm，在 D2 为 0.08 / 0.13 mm（只估刚体部分）。C0 上配准给出 (0.29°, −0.04°, −0.32°)、
   (0.53, 0.43, −0.15) mm，说明自带偏移不只是平移。这条路没有进入本实验的任何一组，只作为后续方案的依据。

其他说明：r2 的三个作业在启动时因梯度钩子注册失败而退出（阶段 1 冻结的参数不能注册钩子），修复并补测试后重跑；
失败的作业没有产生结果文件。参考段的位姿参数在前向模型里不起作用，正则会让它漂移，评估不读它。
