# Paired-anchor queue extension

The model/source review at c8de9bd excluded the then unchanged coordinate-only
queue. This subsequent change adds an explicit `--family paired_anchor` route to
the local `autoresearch_loop.py`. It does not change the five reviewed numerical
production files or the running paired zero-step check. The original main
worktree and its completed first-family queue remain untouched.

The paired route accepts only the real shared+paired zero gate. It reads the
selected paired smoke and trial recipes, runs one shared two-step smoke and one
shared500 trial, then evaluates actual exports with the unchanged frozen scorer.
It does not rerun the explicit500 arm or substitute coordinate controls. The
zero-stage ledger records its actual shared parameterization while labeling its
quality score as baseline. Each successful completed/scored record also stores
feature_mode. Failure events retain the family in their record ID and preserve
the active run context in operational state. The historical
whole-head keeper, original .0001 keep threshold, all six strict inequalities,
failure preservation, cancellation and JSONL/TSV behavior remain in force.

The coordinate route remains available with explicit coordinate feature binding.
Synthetic CPU integration tests exercise both complete queues through the public
supervisor parser, stage checks, durable journal and measured-result decision;
they use no real clinical inputs, stage gates, scores or GPU. A wrong coordinate
zero gate is refused for paired mode before any score or GPU launch. New tests
were observed failing for the absent public family option before implementation.

Actual launch after independent queue review and observed zero completion:

```sh
python3 -B -u autoresearch_loop.py --family paired_anchor \
  --zero-gate outputs/paired_anchor_zero_v1/completed.json \
  --review-gate verification/paired_review_gate_v1.json --gpu 0 --steps 500
```

Numerical sources and selected recipes retain their own exact hash bindings.
The queue binds its own source hash in operational state and the canonical
ledger. A completed negative family remains goal unmet; a provisional whole-head
win requires a repeat and a matched GS-single experiment before a final claim.
