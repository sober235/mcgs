## Render composition and original callback ordering

The carrier runtime owns selected indices and independent plain/contrast frequency parameters. It must not be registered under `trainer.model`: `resume_protocol.validate_parameter_groups`, `relocation_runtime._named_model` and the final checkpoint validator all intentionally require exactly seven original tensors and no extra buffers.

The adapter calls the saved original `_render(channel)` first, then adds `carrier_operator.carrier_correction(positions[idx], scales[idx], rotations[idx], density[idx], frequencies[channel], volume_shape)`. Here `scales` is the model's stored **log** scale, matching the new operator's signature, unlike the old voxelizer's positive-scale argument. Gather live original parameters without detach. Construct the correction density with a separate `model.get_density(channel)` call rather than reusing the old voxelizer input tensor. This keeps `WorkObserver`'s density-input hook attributable to the original renderer backward; otherwise a shared complex density node could mix the correction gradient into the purported original-renderer VJP evidence.

Proposed callback composition:

| Event in original loop | Carrier action and ordering |
|---|---|
| `start` is before original `optimizer.zero_grad()` and both renders | Call the original callback first, which sets training role, timing and frequency guard. Then clear only the carrier optimizer gradients. Verify expected carrier local step before the next forward. |
| `pre_step` is after loss backward and original global clipping over seven tensors, before original Adam | Require finite gradients for both carrier parameter tensors, record their norms and actual frequency range, apply a separately declared carrier clipping bound, and call/preserve the original callback. Do not reclamp or renormalize original gradients. |
| `end` is after original Adam, original scheduler and disabled adaptive-control call | Apply one carrier Adam step from the already-computed gradients, apply its declared schedule if any, verify clocks/bounds/finiteness, then invoke the original callback. This includes carrier work in the original step timer and lets it finalize its ordinary trace after both parameter blocks are updated. No second loss or backward is performed. |

The carrier gradient belongs to the same pre-update loss as the Gaussian gradients, even though its optimizer steps later. Carrier parameters must have no dependence on already-updated Gaussian tensors in their optimizer step. A `tanh` frequency transform is recomputed at each render, not cached across updates. Original Gaussian clipping remains across seven original tensors; separate carrier clipping is an explicit algorithm choice, not equivalent to clipping all parameters jointly.

Scope both instance replacements (`train` and `_render`) with `try/finally`, preserving whether they existed in `vars(trainer)`. Avoid a callback closure accidentally calling the replacement recursively. A private derived `WorkObserver` bound only into a private copy of `run_continuation` can expose the actual observer's `role`, `iteration` and `channel` to the carrier observer. The inherited `observe()` wraps the carrier-adapted render and sets channel before calling it. This avoids inferring export from a call count or inventing roles. Its parent methods and Gaussian/FFT accounting remain unchanged. The old `run_continuation` function itself need not be copied or edited.

## Canonical export and state that must be saved

`OLD/proximal_dc/runner.py:169 canonical_control` captures `original_render=trainer._render`, wraps it to record raw images, and calls `base.export_trainer_volume(trainer, channel)` for each scan. Consequently, if the carrier adapter is still installed, both its captured raw image and canonical hard-DC image contain the carrier. Removing the adapter immediately after `trainer.train` would silently export the wrong reconstruction. The context must span the entire original `run_continuation`, including final export.

Keep the original `latest.pth` containing `iter/model_state/optim_state` unchanged so `_checkpoint_evidence` can still safely CPU-load it with `weights_only=True` and compare all original tensors/moments. Add a separate route-versioned carrier checkpoint and a manifest binding both files at the same absolute iteration. Save final carrier state after the original helper returns, or at the final `end` plus a completion manifest after original checkpoint verification. The latter ordering must not publish a complete paired checkpoint before the Gaussian file exists. A failure leaves incomplete evidence, not a resumable success.

Carrier checkpoint contents must include selected row IDs, raw frequency parameters, parameterization/bounds/units, contrast mapping, optimizer state and options, local update count, schedule policy/state, and source/binary identity. Safe CPU readback must compare saved tensors, Adam moments/steps and exact options against live state. Reconstructing a separately tested carrier module from this checkpoint must reproduce its selected-row correction on a small fixture. A paired resume must refuse a missing component, mismatched iteration/indices/policy, wrong shape or foreign binary; never silently initialize carrier frequencies to zero.

Snapshot separate carrier state before and after canonical export and require equality. The old `snapshot_training_state` cannot detect mutations to this external component. Keep the Gaussian zero-stage invariant `restore.after == before == after`; do not add carrier state into those old structures or manufacture a replacement restore result.

## Binary loading, conservative bounds and closure

Current `carrier_operator.load_carrier_extension(build_directory)` is explicit and content-addressed, but it is a **build-or-load** API, not a pure immutable binary loader. It imports Torch, validates a pinned CUDA11.8 environment, validates artifacts, then invokes `cpp_extension.load`; no implicit call occurs in `carrier_correction`. The route parent must not import this module. Before MRI, select and freeze an already verified artifact, its provenance and architecture. In the child, explicitly load that exact directory, require the returned identity/path/binary digest to match the frozen values, and refuse a missing/partial artifact or a changed result. If strict “never invoke a build tool during MRI” is desired, that needs a separately reviewed load-existing-only API; it does not exist yet. Do not represent cache reuse as such an API.

The existing supervisor child environment pins CUDA visibility and thread settings but does not set `CUDA_HOME`, `CXX`, `PATH`, `TORCH_CUDA_ARCH_LIST` or remove the operator's refused overrides. A new child wrapper must establish the documented build/load environment before importing `cpp_extension`, record removed override **names**, and validate the actual device capability against the frozen binary. Keep changes within the owned child process. Changing the build identity after real source gates would invalidate those gates. A preferred GPU is not an architecture filter: an incompatible selected GPU must fail before MRI loading, or the selection adapter must explicitly enforce compatibility in a separately reviewed change.

`carrier_operator._geometry` symmetrizes its float32 M; `_tile_pairs` computes eigenvalues/inverse in double, using inverse-M bounds for reliable positive-definite matrices and full-volume bounds for finite ill-conditioned matrices. The old renderer uses its historical rotation/scale bbox and its own arithmetic. Thus the exact implemented route is **old render + new-M correction**. Zero-frequency equivalence is still exact at the correction level, but strict algebraic replacement by a full Gabor renderer is not automatically true where old/new support or numerical M differ. Disclose this policy and verify selected G2 geometry diagnostics; do not silently change the old bbox or clamp the new bounds. Worst-case full-volume fallback at K=18000 can make pair work prohibitive despite small parameter storage. The operator currently checks int32 pair-count overflow, not an MRI-specific memory budget.

New `code_hashes()` should extend the unchanged original218-file closure with every executed new Python/C++/CUDA file and the frozen new binary; include any reused caseprior protocol source if its receipt helpers are used. No Torch import is needed to hash explicit paths. Bind the independent reviewed microgate report/provenance as control descriptors, not as a substitute for new route review. Avoid recursive inclusion of mutable build directories or unrelated test artifacts in the production closure.

For easiest native receipt reuse, place carrier-specific execution identity in the replaceable route `policy` or code/control bindings, while retaining exactly the existing common invariant fields. `run_caseprior._validate_native_control_receipt` reconstructs old invariants by replacing only `route` and `policy`; adding new top-level carrier invariant keys would break its equality with historical gates. If new top-level fields are needed, implement an explicit whitelisted common-invariant projection and test it; never discard unknown fields generically.

## Native control reuse, gates and narrow ownership

`run_caseprior.validate_native_control_receipt(path, hashes, invariants, ordinary_smoke)` is the existing rigorous reuse path. Its helper validates old native500 and old ordinary smoke against the original old closure, compares new ordinary-smoke restored state/work/scheduler, checks complex candidate relative L2, binds all scored native arrays and verifies six metrics/59 planes plus evaluator identity. A private adapter can rebind the new route and observed-gate validator while keeping `old=run_relocation` unchanged. The new ordinary control must truly disable the carrier and match the original evidence; an enabled or zero-frequency-learning smoke is not a native-control equivalence proof. Extra carrier evidence must live outside old `counters`. If receipt validation fails, use a newly completed source-bound ordinary500 control.

Suggested exclusive implementation ownership, after a separate design/plan decision:

- `carrier_runtime.py` and `tests/test_carrier_runtime.py`: selection, frequency state/optimizer, scoped render/train adapters, new observation/checkpoint/export evidence. No changes to operator files while their current review/fix is active.
- `carrier_runner.py` and `tests/test_carrier_runner.py`: private clinical/execute adapters, explicit verified binary loading, added runtime artifact production and paired checkpoint publication.
- `run_carrier.py` and `tests/test_carrier_protocol.py`: stdlib protocol, fixed policy, closure, recipe/stage checks, exact new evidence validation and native receipt binding.
- Root owner: integration docs, source/review gates, recipes, actual experiment ledgers/state and launch decisions. Existing supervisor/evaluator/old numerical files stay untouched.

Acceptance sequence: (1) finish the independently reviewed operator microgate; (2) CPU integration fixtures proving unchanged seven-state restore, callback ordering, separate optimizer clocks, live gradient connectivity, correct export persistence and corrupted/missing checkpoint refusal; (3) independently review the full new route and protocol; (4) genuine source-bound G2 zero-carrier export, disabled ordinary two-update smoke and enabled two-update smoke with actual correction backward/parameter changes; (5) native receipt or new ordinary500 control, then one predeclared carrier500 trial and frozen separate scoring. CPU fixtures and microgate results do not stand in for actual MRI controls. Existing promotion, repeat, matched GS-single and visual-inspection rules remain applicable.

Substantive choices still requiring a recorded design: K/selection seed and policy; frequency bound/transform and LR; per-contrast versus shared carrier parameters (component design currently anticipates independent); Adam schedule and separate clipping; exact zero-stage execution semantics; support/pair-memory refusal threshold; architecture-compatible verified artifact strategy and build-or-load versus pure loader; paired checkpoint resume API; and which real zero/raw parity checks are required beyond the inherited canonical L2 gate. These are unresolved implementation decisions, not permission questions or evidence of quality gain.
